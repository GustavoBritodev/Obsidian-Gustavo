1. **Requisitos funcionais:**
- Os requisitos funcionais descrevem as funcionalidades e tarefas específicas que o software deve ser capaz de realizar. Eles definem as ações que o sistema deve executar em resposta a determinadas entradas. Vamos ver alguns exemplos:
	- Um requisito funcional pode ser "O sistema deve permitir que o usuário faça login com seu nome de usuário e senha" .
	- Outro exemplo seria: "O sistema deve permitir que o usuário adicione itens ao carrinho de compras e finalize a compra".

2. **Requisitos não funcionais:**
- Os requisitos não funcionais descrevem as características e qualidades do software, além das funcionalidades em si. Eles se concentram em atributos do sistema, como desempenho, usabilidade, segurança e confiabilidade. Vamos ver alguns exemplos:
	- Um requisito não funcional pode ser "O sistema deve ter uma resposta de busca instantânea, retornando os resultados em menos de 1 segundo".
	- Outro exemplo seria "O sistema deve ser compatível com as diretrizes de acessibilidade WCAG 2.0".

3. **Requisitos de Domínio:**
- Os requisitos de domínio são específicos para determinado contexto ou área de negócio. Eles são baseados no conhecimento especializado do domínio em que o software será aplicado. Por exemplo:
	- Em um sistema de gerenciamento de estoque de uma loja de varejo, um requisito de domínio pode ser "O sistema deve calcular automaticamente o preço de venda considerando os descontos promocionais e regras de precificação definidas pelo varejista".

4. **Requisitos de Interface:**
- Os requisitos de interface dizem a respeito à interação entre o software e os usuários ou outros sistemas. Eles descrevem como o sistema se comunica com o ambiente externo. Por exemplo:
	- Um requisito de interface pode ser "O sistema deve fornecer uma API REST para integração com outros sistemas".
	- Outro exemplo seria: "A interface do usuário deve ser intuitiva e de fácil utilização, seguindo os princípios de design de interface modernos".

5. **Requisitos de Usabilidade:**
- Os requisitos de usabilidade estão relacionados à experiência do usuário ao utilizar o software. eles visam garantir que o sistema seja intuitivo, eficiente e agradável de usar. Alguns exemplos:
	- Um requisito de usabilidade pode ser "As informações exibidas na tela devem ser organizadas de forma clara e legível para facilitar a compreensão do usuário".
	- Outro exemplo seria "O sistema deve fornecer feedback visual adequado para indicar ao usuário que uma ação foi executada com sucesso".

6. **Requisitos de Desempenho:**
- Os requisitos de desempenho dizem respeito ao desempenho esperado do sistema em relação ao tempo de resposta, capacidade de processamento e uso eficiente dos recursos. Alguns exemplos:
	- Um requisito de desempenho pode ser "O sistema deve ser capaz de processar simultaneamente 1000 transações por segundo".
	- Outro exemplo seria "O tempo de resposta do sistema não deve exceder 2 segundos, mesmo com uma carga máxima de usuários".

## **Explicação sobre os diferentes tipos de requisitos dada pelo GPT:** 

Os requisitos de software definem as características e funcionalidades que um sistema deve possuir. Eles são divididos em diferentes categorias, cada uma com sua importância no desenvolvimento.

### **1. Requisitos Funcionais**

São as funcionalidades e comportamentos específicos que o software deve ter.  
**Exemplos:**

- O sistema deve permitir que o usuário faça login usando e-mail e senha.
- O software deve enviar um e-mail de confirmação após o cadastro.
- O sistema deve permitir a recuperação de senha via código enviado por e-mail.

### **2. Requisitos Não Funcionais**

São restrições e qualidades do sistema que influenciam sua operação, como segurança, desempenho e manutenção.  
**Exemplos:**

- O sistema deve estar disponível 99,9% do tempo.
- O software deve suportar até 10.000 usuários simultâneos.
- Todas as senhas armazenadas devem ser criptografadas com algoritmo SHA-256.

### **3. Requisitos de Domínio**

São requisitos específicos do contexto ou área de aplicação do software.  
**Exemplos:**

- O sistema bancário deve seguir as normas da Febraban para transferências eletrônicas.
- O software médico deve estar em conformidade com a LGPD para proteção de dados dos pacientes.
- O sistema de e-commerce deve calcular impostos de acordo com a legislação vigente.

### **4. Requisitos de Interface**

Definem como o usuário interage com o sistema e como ele se comunica com outros sistemas.  
**Exemplos:**

- O sistema deve possuir uma interface responsiva para dispositivos móveis e desktops.
- O software deve permitir integração com o sistema de pagamento via API REST.
- O usuário deve visualizar um ícone de carregamento enquanto os dados estão sendo processados.

### **5. Requisitos de Usabilidade**

Garantem que o sistema seja intuitivo e fácil de usar.  
**Exemplos:**

- O sistema deve permitir que um novo usuário aprenda a usá-lo em até 10 minutos.
- Todas as funções essenciais devem ser acessíveis com no máximo 3 cliques.
- O software deve ter um modo de alto contraste para acessibilidade.

### **6. Requisitos de Desempenho**

Estabelecem métricas para a eficiência do sistema, como tempo de resposta e escalabilidade.  
**Exemplos:**

- O tempo de resposta das consultas ao banco de dados deve ser inferior a 2 segundos.
- O sistema deve suportar 500 requisições simultâneas sem degradação de desempenho.
- O carregamento da página inicial não deve ultrapassar 3 segundos em conexões de 10 Mbps.

Esses requisitos ajudam a garantir que o software atenda às expectativas dos usuários e funcione de maneira eficiente.
